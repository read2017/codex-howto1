# Codex Day 4 速查卡：sandbox、approval、网络边界

## 一句话记忆

- `sandbox`：技术上能不能做
- `approval`：做之前要不要先问
- 网络边界：做了之后能不能把东西带出去

## 默认判断流程

1. 它还在当前工作区内吗？
2. 它碰到敏感面了吗？
3. 它有没有引入外部内容？
4. 它会不会把本地信息发出去？

只要第 2、3、4 条命中，通常不要直接判“允许”。

## 动作分类

### 直接允许

- 读取当前仓库源码
- 修改当前仓库普通代码、测试、文档
- 运行常规本地测试、lint、build
- 查看本地 `git status`

### 需要审批

- 访问外网查官方文档
- 下载新依赖
- 修改 `CI/CD`、部署、权限相关配置
- 读取工作区外文件
- 运行可能越过 sandbox 的命令

### 默认禁止

- `curl ... | sh`
- 向第三方发送本地日志、源码、密钥、配置
- 执行外部返回内容
- 任意外站写请求
- 无护栏高权限运行

## 高频敏感面

- `.github/workflows/*`
- 发布与部署脚本
- 权限配置
- 密钥、token、SSH 相关文件
- webhook 与外部 API 调用

## 常见误判

- 误判 1：读操作就安全
  - 更正：读普通源码和读敏感配置不是一回事
- 误判 2：在仓库里就低风险
  - 更正：`CI/CD`、部署、权限配置依然是敏感面
- 误判 3：会弹审批就等于安全
  - 更正：审批只是人工确认，不是技术护栏

## 高频结论

- 外网访问通常不是“直接允许”，至少应 `需要审批`
- 下载依赖通常不是“一律禁止”，更稳的是 `需要审批 + 限定来源`
- 数据外发默认按高风险处理
- 工作区外敏感读取不能因为“只是读”就放行
